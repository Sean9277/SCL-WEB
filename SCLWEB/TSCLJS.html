JavaScript

History

--The Birth of JavaScript (1995)--

Inventor: Brendan Eich.
Company: Netscape Communications Corporation.
Purpose: JavaScript was created to add interactivity to web pages.
Timeline:Eich developed the language in just 10 days.
Initially called Mocha, it was later renamed to LiveScript, and finally to JavaScript to capitalize on the popularity of Java at the time.

-- Standardization (1996–1999)--


1996 : Microsoft introduced a similar scripting language called cript, which ran on Internet Explorer.
1997: JavaScript was submitted to ECMA International for standardization.
1999: The third edition of ECMAScript (ES3) became the baseline for modern JavaScript.

-- Dormant Period (2000–2005) -- (2000)


After the release of ES3, JavaScript development slowed down as browser wars (primarily between Internet Explorer and Netscape) dominated the web.
During this time, JavaScript was mostly used for basic form validation and small interactive elements.

-- The AJAX Revolution (2005)--

AJAX (Asynchronous JavaScript and XML): Popularized by Google (notably Gmail and Google Maps), AJAX allowed dynamic, asynchronous updates without reloading the page.
This marked a turning point, as developers started using JavaScript to create rich, interactive web applications.

--Rise of Libraries and Frameworks (2006–2010)--


Libraries like jQuery simplified DOM manipulation, event handling, and AJAX requests, making JavaScript more accessible. Frameworks like MooTools , Prototype, and Dojo emerged.

--ECMAScript 5 and Modern Standards (2009)--


ECMAScript 5 (ES5) introduced new features like:
• Strict mode.
• ON support.
Array methods (e.g., forEach, map, filter). This version became widely adopted and set the stage for modern JavaScript.

--The Node. Revolution (2009)--


Node.: Created by Ryan Dahl, it brought JavaScript to the server-side.
Enabled JavaScript to be used beyond the browser, making it a full-stack language

--ECMAScript 6 and Beyond (2015–Present)--


ECMAScript 6 (ES6) , also known as ECMAScript 2015, was a massive update that introduced:
Arrow functions.
Classes.
Promises.
Modules (import/export)
Template literals.
Destructuring assignment.
Subsequent updates (ES7, ES8, etc.) added features like async/await, optional chaining, and many other improvements.

--JavaScript in the Modern Era--


Frameworks: The rise of React, Angular, and Vue. made building complex web applications easier.
TypeScript: A superset of JavaScript, TypeScript, introduced static typing, improving code maintainability.
Ecosystem:Tools like Webpack, Babel, and ESLint streamlined development.
JavaScript became a key player in mobile app development (e.g., React Native) and desktop apps (e.g., Electron).

--The Future of JavaScript-- (2019)


Focus on:
Performance optimizations.
Improved developer experience.
More robust standard libraries.
Continued evolution through TC39 proposals, ensuring JavaScript stays relevant.

JavaScript Functions

JavaScript Function Syntax

A JavaScript function is defined with the function keyword, followed by a name, followed by parentheses ().

Function names can contain letters, digits, underscores, and dollar signs (same rules as variables).

The parentheses may include parameter names separated by commas:
(parameter1, parameter2, ...)

The code to be executed, by the function, is placed inside curly brackets: {}

Function parameters are listed inside the parentheses () in the function definition.

Function arguments are the values received by the function when it is invoked.

Inside the function, the arguments (the parameters) behave as local variables.

Function Invocation

The code inside the function will execute when "something" invokes (calls) the function:

-When an event occurs (when a user clicks a button)
-When it is invoked (called) from JavaScript code
-Automatically (self invoked)

You will learn a lot more about function invocation later in this tutorial.

Function Return

When JavaScript reaches a return statement, the function will stop executing.

If the function was invoked from a statement, JavaScript will "return" to execute the code after the invoking statement.

JavaScript Debugging

Errors can (will) happen, every time you write some new computer code.

Code Debugging

Programming code might contain syntax errors, or logical errors.

Many of these errors are difficult to diagnose.

Often, when programming code contains errors, nothing will happen. There are no error messages, and you will get no indications where to search for errors.

Searching for (and fixing) errors in programming code is called code debugging.
